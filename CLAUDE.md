# Landscape

Data layer mapping the creative industry (Israel first). See PLAN.md for the vision.

- Brand: the public name is "CreativeIn." (always capital C and I, never "Creativein"; wordmark = the SVG logo in `lib/logo.mjs` ("Creative" + lime "In" badge, no dot; emails use `public/brand/creativein-wordmark*.png`); company-type tags and colours come from `lib/kinds.mjs` + `app/chrome.css`; URLs and email addresses stay lowercase; `BRAND` / `WORDMARK` / `TAGLINE` in `lib/chrome.mjs`; tagline "תעשיית הקריאייטיב בישראל. האנשים, החברות וההזדמנויות."). Domain creativein.co.il is registered but not connected yet: the site URL, canonical links (`metadataBase` in `app/layout.js` + `alternates.canonical` per page) and sitemap all come from `siteUrl()` (`NEXT_PUBLIC_SITE_URL`); never hardcode the domain. "Landscape" is the internal project name (repo, package, ids, env vars, storage keys like `landscape-theme`). Never rename keys.
- Wording: "הזדמנויות" only for verified items (open tenders, published job postings with a source). Every other update is "עדכון", a business signal, never phrased as proof that a company is hiring or commissioning.
- Feedback: `/feedback` (footer link "משהו חסר? יש רעיון לשיפור?", and the /join sent screen) → `POST /api/feedback` (readJson, rate-limited, service role) → table `feedback` (migration 008, no browser access). Without Supabase the form says it's unavailable.

- Records: `data/orgs/<id>.json`, schema `schema/org.schema.json`, categories `schema/taxonomy.json`.
- Never hand-edit `site/data/`, `site/index.html`, `data/exports/` or `STATS.md` — they're built by `python3 scripts/landscape.py build`.
- To add or update data: write a JSON array to `research/staging/`, then `ingest` → `validate` → `build`.
- Research runs follow `.claude/skills/research/SKILL.md`.
- Accuracy over volume; every record needs sources. Public business info only.
- The app lives in `site/app.html` (one file). It loads `data/dataset.json`, `data/signals.json` and `data/logos.json` built into `site/data/`. The build wraps it as `site/index.html` for GitHub Pages; the Artifact publishes `site/app.html` + those three files. Logos: masters in `data/logos/` (up to 512px, `manifest.json` holds src_px and source); the build writes 64px data URIs to `logos.json` (Artifact) and hi-res `site/data/logo/<id>.webp|svg` (192px max, never upscaled) that the site uses, with `logo_px`/`logo_ext`/`logo_ar` on each org; under 48px the app shows the name tile.
- Signals: `data/signals/YYYY-MM.json`, schema `schema/signal.schema.json`, merged with `landscape.py signals`. They point to orgs and never edit them.
- Per-person data (pipeline, notes, crafts) lives only in the Artifact database under `data/users/<id>/` — private to each person. Never read or write it from research runs.
- Ids never change; merges go in `data/redirects.json`.
- Product decisions: `team/DECISIONS.md`.
- Community app: Next.js at the repo root (`app/`, `components/`, `lib/`), deployed on Vercel. `npm run build` copies the companies app (`site/app.html`) to `public/companies/` (served at `/companies`; `/map` redirects there). Every company also has its own page, `/companies/<id>` (`app/companies/[id]`, built from `site/data` by `lib/orgs.js`, in the sitemap); on the site the list links to it and old `/companies#<id>` links redirect there, while the Artifact copy keeps the side sheet. The page's מעקב uses the app's local tracking list (`landscape-v2`). People stay as cards, with no pages. The build also builds `lib/generated/people.json` (people already in `key_people`, with a source) and `orgs.json` for search, and, on production deploys only (`VERCEL_ENV=production`, or `MIGRATE=1` locally), applies pending `supabase/migrations/*.sql` (`scripts/migrate.mjs`): a ledger (`public._migrations`) runs each file once, all pending files in one transaction, and a failure fails the build. Preview builds never touch the database. Add a new numbered file for every schema change; never edit one that already ran, and never re-grant writes to `anon`/`authenticated` (007 revokes them). Must build with no env vars.
- Promo strip, header (with its search field), phone menu (hamburger) and footer have one source for both apps: `lib/chrome.mjs` (markup, links, menu script) and `app/chrome.css` (styles). The build writes them into `/companies` between the `chrome:` markers in `site/app.html` (and syncs those blocks back into `site/app.html`, which the Artifact publishes); edit them there, not in `site/app.html`.
- Phone tab bar (under 861px, both apps): `TABS` + `tabbarHtml` in `lib/chrome.mjs` — בית, חברות, עדכונים, מכרזים, then the call to action (the weekly email → `/join`, or "החשבון" when signed in). In the companies app "חברות" and "עדכונים" switch the app's own sections in place (`data-apptab`), and its own section bar is a row under the header; in the Artifact host the app keeps its own bottom bar. The hamburger holds the rest (אנשים, השבוע בתעשייה, סקר, פרטיות).
- Sign-up: `/join` is the weekly-email onboarding (crafts → a live preview from `/api/digest/preview` with frequency → address + the consent box → "sent", which says the link works only on this device and browser). It goes through `DigestSubscribe`, so crafts and frequency ride the magic link and nothing is saved before confirmation. Signed in, it redirects to `/digest/settings`. The header call to action, the hero and the promo strip link to it.
- Look: `team/DESIGN.md` (reference: Awwwards). Monochrome greys, ink buttons (filled or outlined, 8px), white cards on a grey canvas, no shadows; purple only as a small marker.
- Search rules live in `lib/match.js` (Hebrew spellings of Latin names match through `lib/translit.js`, checked by `node scripts/test-search-he.mjs`) (craft names and aliases from `schema/taxonomy.json` → `craft_aliases`, Hebrew title words); `site/app.html` mirrors the craft rule.
- People's profiles live in Supabase only (RLS). Never put personal data in the repo; research runs don't touch it.
- Naming: the company directory is "חברות" (never "מפה"); market updates are "עדכונים"; the weekly digest is "המייל השבועי" or its name "השבוע בתעשייה" (never "גיליון"). Hebrew UI copy is gender-neutral (plural / infinitive), no "את/ה" slashes.
- `/api/ask` answers questions about the directory with Claude (read-only tools over `site/data/`, no per-person data, rate-limited). Off unless `ANTHROPIC_API_KEY` is set and `AI_SEARCH=on` (off for the launch); when on, `/search` shows an AI answer above the results for question-like queries (`components/AskAnswer.js`, `lib/askable.js`). A key that isn't scoped to a workspace also needs `ANTHROPIC_WORKSPACE_ID`.
- Weekly digest "השבוע בתעשייה": `lib/digest.js` composes it from `site/data` only (an update counts for a craft only if it names it or credits someone in it); a subscriber with companies in their tracking list (`org_follows`) gets their updates first, under "במעקב שלכם", `/digest` is the web edition, `lib/digestEmail.js` the email, `lib/digestSend.js` + `/api/cron/digest` (Vercel Cron, daily 04:00 UTC; sends on Sunday, catches up two days; a "pending" row in `digest_sends` is claimed before each send, so never twice). Recipients come only from `public.digest_recipients()` (confirmed address from `auth.users`, recorded consent). The cron refuses to send unless `RESEND_API_KEY`, `DIGEST_FROM`, `DIGEST_SENDER_NAME`, `DIGEST_SENDER_ADDRESS` and `NEXT_PUBLIC_PRIVACY_EMAIL` are set (sender identity in every footer, anti-spam law §30A); cron and `/api/digest/test` need `CRON_SECRET` as a Bearer header. Unsubscribe links are HMAC-signed (`DIGEST_SECRET` or `CRON_SECRET`).
- Consent: `newsletter_prefs` is written only by the server (`lib/consent.js`, service role); people can read their own row. A sign-up form's digest opt-in rides on the magic link (`lib/authLink.js` → `/auth/callback?subscribe=…`), so it takes effect only once the address is confirmed.
- Tenders ("מכרזים"): `data/tenders/YYYY-MM.json` (schema `schema/tender.schema.json`), merged with `landscape.py tenders FILE` (adds new ids, updates known ones); the build writes `site/data/tenders.json` (open + closed in the last 30 days). `lib/tenders.js` recomputes the state against the current time (Israel time): upcoming before `submission_opens` ("ההגשה נפתחת ב־…", never counted or labelled open), open until `deadline_at`, then closed; cancelled wins. Checks: `node scripts/test-tenders.mjs`. Only open tenders and job postings with a source are "הזדמנויות"; every other signal is an "עדכון" and is never worded as proof of hiring or commissioning (`classOf` in `lib/digest.js`). Shown on `/tenders`, the home strip, `/search` and the digest. Official source link only; no contact names; sources and rules in `research/tenders-sources.md`; mr.gov.il candidates via `scripts/tenders_mrgov.py` (polite, ≤40 requests).
- Tools ("כלים ו־AI"): catalog `data/tools/catalog.json` (schema `schema/tool.schema.json`) and dated updates `data/tools/updates/YYYY-MM.json` (schema `schema/tool-update.schema.json`), merged with `landscape.py tools FILE`; the build writes `site/data/tools.json` (catalog + updates from the last 60 days). `lib/tools.js` serves `/tools`, `components/ToolsStrip.js` (home strip), the digest section "כלים ו־AI השבוע" (web + email, max 3, the reader's crafts first) and a "כלים" group in `/search`. Every update comes from the maker's own changelog, blog or press release, with the exact date; official links only, no affiliate links, no paid placement; `made_in_israel` and `pricing` only when a source confirms them. Off by default: one flag, `TOOLS` in `lib/chrome.mjs` (`NEXT_PUBLIC_TOOLS=on`); off, `/tools` is a 404 and nothing else shows. Sources and rules in `research/tools-sources.md`.
- Rates survey: `/survey` (landing), `/survey/start` (questionnaire), `/survey/results`. Questions, bands and close date in `lib/survey/config.js` (the companies app gets the date at build time). Answers in Supabase `survey_responses`: written only through `/api/survey` (service role), owner can read their own. Results come from a daily snapshot (`survey_snapshots`, at most once per 24h and only after ≥5 new answers); groups under 5 are left out, exact numbers count only from 10, shares rounded to 5%, group sizes shown as buckets, free text never shown. Checks: `node scripts/test-survey.mjs`. Never ask for client or company names.
- Stage 1 (now): an information channel + newsletter. Nobody builds a profile: `/onboard` redirects to `/digest`, `/p/*` redirects to `/people`, `/me` is only the account (digest settings, alerts, survey, delete; signed out it shows a sign-in form), and there is no "זה אני" on listed people (removal stays). It's one flag, `PROFILES` in `lib/chrome.mjs` (`NEXT_PUBLIC_PROFILES=on` brings profiles back; the code stays). Header call to action is sign-up ("הרשמה", with a "כניסה" link beside it), or "החשבון שלי" when signed in (`JOIN`/`ME` in `lib/chrome.mjs`; the companies app gets it from `/api/session`).
- Sign-up (`/join`) makes an account: crafts → "רוצים גם ניוזלטר?" (yes / not now) → address. The newsletter is optional; yes still needs the consent box on the address step. The magic link carries the crafts (saved with `saveCrafts` when there's no newsletter, nothing sent) and, if chosen, the frequency, and lands on `/me?welcome=1`. `/me` is the personal area: "המעקב שלי" (the tracking list, kept in the account as `org_follows` and in the browser; `lib/trackSync.js` merges them, the browser's list joins the account once per device), alerts, newsletter settings, survey, delete.
- Theme: light by default on both apps, whatever the device. The header toggle (`THEME_BUTTON`, `THEME_SCRIPT` in `lib/chrome.mjs`) cycles בהירה → כהה → לפי המכשיר and stores it in localStorage (`landscape-theme`); CSS reads `html[data-theme]` (`dark`, or `system` + prefers-color-scheme). Inside the Artifact host the companies app still follows the device.

- Alerts on followed companies ("התראות על החברה"): `org_follows` (max 100 per person) and the alert choice (`newsletter_prefs.alerts`: daily / weekly / off, own consent record) are written only by the server (`lib/follows.js`, `/api/follows`); people read their own follows. Signed out, `/api/follows/start` only sends a magic link; the follow and opt-in are recorded in `/auth/callback?follow=…&alerts=daily` after the address is confirmed. `/api/cron/alerts` (daily 05:00 UTC) sends one email per person bundling new updates on their companies (`lib/alerts*.js`), claimed in `alert_sends` before sending, recipients only from `public.alert_recipients()`; same five-variable sending gate as the digest; unsubscribe tokens are per list (`listToken("alerts", id)`). Checks: `node scripts/test-alerts.mjs` (after a build). In the companies app there is one "מעקב" button: it saves the company to the local tracking list and, when signed in with alerts consent, also follows it; otherwise it offers alerts by email (optional); alerts are switched on/off inside the tracking editor. Alerts count from the day an update first appeared on the live site (`signal_seen`; the first run records history), claims carry the run id so a failed run releases only its own, the Resend idempotency key is derived from the people and updates in the batch, and a run stays inside the shared daily send budget (`DAILY_SEND_BUDGET`, default 100 = Resend free plan, minus digest emails sent today; `ALERTS_DAILY_LIMIT` caps alerts, default 40). Checks: `node scripts/test-callback.mjs` (magic-link landing, after a build).

- Home page sells the weekly digest: hook + one subscribe form in the hero, then live proof from `lib/proof.js` (real counts and the latest updates from `site/data`, computed at render; never invented numbers, users or testimonials), before/after, real examples, a digest preview (`components/DigestPreview.js`, editions composed server-side by `composeDigest`), tenders, FAQ. One main CTA per page (the digest); urgency only when real (tender deadlines, survey close date).
- Analytics: Vercel Web Analytics (`@vercel/analytics`, `<Analytics/>` in `app/layout.js`; the companies shell loads `/_vercel/insights/script.js`). The owner must enable Web Analytics for the project in the Vercel dashboard. Events: `track()` on form submits (`digest_subscribe_submit` with `where`), and any element with `data-track="name"` is reported on click by `components/TrackClicks.js` (`survey_start`, `follow_click`, `tender_open`, …); the companies app uses `window.va("event", …)`. Custom events only count on plans that include them. Named events: (Vercel Web Analytics, no cookies, no query text): `digest_subscribe_submit`, `search_submit` {has_craft, has_city}, `company_open`, `opportunity_source_click` {category}, `tender_source_click`, `feedback_submit`, plus the `data-track` clicks. `components/TrackClicks.js` wires clicks, company links and search forms on the Next pages.
- Magic links (Supabase PKCE) work only on the device and browser that asked for them; every "sent" message says so. Hebrew email templates to paste into Supabase: `docs/supabase-email-templates.md`.
- API POST routes take JSON only (`readJson` in `lib/guard.js`: `application/json`, same-origin, 32KB) or check `sameOrigin`; unsubscribe endpoints are exempt (mail clients post them). `robots.txt` and `sitemap.xml` come from `app/robots.js` and `app/sitemap.js`.
