# Landscape

Data layer mapping the creative industry (Israel first). See PLAN.md for the vision.

- Records: `data/orgs/<id>.json`, schema `schema/org.schema.json`, categories `schema/taxonomy.json`.
- Never hand-edit `site/data/`, `site/index.html`, `data/exports/` or `STATS.md` — they're built by `python3 scripts/landscape.py build`.
- To add or update data: write a JSON array to `research/staging/`, then `ingest` → `validate` → `build`.
- Research runs follow `.claude/skills/research/SKILL.md`.
- Accuracy over volume; every record needs sources. Public business info only.
- The app lives in `site/app.html` (one file). It loads `data/dataset.json`, `data/signals.json` and `data/logos.json` built into `site/data/`. The build wraps it as `site/index.html` for GitHub Pages; the Artifact publishes `site/app.html` + those three files.
- Signals: `data/signals/YYYY-MM.json`, schema `schema/signal.schema.json`, merged with `landscape.py signals`. They point to orgs and never edit them.
- Per-person data (pipeline, notes, crafts) lives only in the Artifact database under `data/users/<id>/` — private to each person. Never read or write it from research runs.
- Ids never change; merges go in `data/redirects.json`.
- Product decisions: `team/DECISIONS.md`.
- Community app: Next.js at the repo root (`app/`, `components/`, `lib/`), deployed on Vercel. `npm run build` copies the companies app (`site/app.html`) to `public/companies/` (served at `/companies`; `/map` redirects there), builds `lib/generated/people.json` (people already in `key_people`, with a source) and `orgs.json` for search, and runs `supabase/migrations/*.sql` (idempotent) when `POSTGRES_URL_NON_POOLING` is set. Must build with no env vars.
- Header and footer have one source for both apps: `lib/chrome.mjs` (links) and `app/chrome.css` (styles). The build writes them into `/companies` between the `chrome:` markers in `site/app.html`; edit them there, not in `site/app.html`.
- Search rules live in `lib/match.js` (craft names and aliases from `schema/taxonomy.json` → `craft_aliases`, Hebrew title words); `site/app.html` mirrors the craft rule.
- People's profiles live in Supabase only (RLS). Never put personal data in the repo; research runs don't touch it.
- Naming: the company directory is "חברות" (never "מפה"); market updates are "עדכונים". Hebrew UI copy is gender-neutral (plural / infinitive), no "את/ה" slashes.
- `/api/ask` answers questions about the directory with Claude (read-only tools over `site/data/`, no per-person data, rate-limited). Hidden when `ANTHROPIC_API_KEY` is unset.
- Weekly digest "השבוע בתעשייה": `lib/digest.js` composes it from `site/data` only (an update counts for a craft only if it names it or credits someone in it), `/digest` is the web edition, `lib/digestEmail.js` the email, `lib/digestSend.js` + `/api/cron/digest` (Vercel Cron, daily 04:00 UTC; sends on Sunday, catches up two days; a "pending" row in `digest_sends` is claimed before each send, so never twice). Recipients come only from `public.digest_recipients()` (confirmed address from `auth.users`, recorded consent). The cron refuses to send unless `RESEND_API_KEY`, `DIGEST_FROM`, `DIGEST_SENDER_NAME`, `DIGEST_SENDER_ADDRESS` and `NEXT_PUBLIC_PRIVACY_EMAIL` are set (sender identity in every footer, anti-spam law §30A); cron and `/api/digest/test` need `CRON_SECRET` as a Bearer header. Unsubscribe links are HMAC-signed (`DIGEST_SECRET` or `CRON_SECRET`).
- Consent: `newsletter_prefs` is written only by the server (`lib/consent.js`, service role); people can read their own row. A sign-up form's digest opt-in rides on the magic link (`lib/authLink.js` → `/auth/callback?subscribe=…`), so it takes effect only once the address is confirmed.
- Tenders ("מכרזים"): `data/tenders/YYYY-MM.json` (schema `schema/tender.schema.json`), merged with `landscape.py tenders FILE` (adds new ids, updates known ones); the build writes `site/data/tenders.json` (open + closed in the last 30 days). `lib/tenders.js` recomputes open/closed against the current time (deadlines are Israel time). Shown on `/tenders`, the home strip, `/search` and the digest. Official source link only; no contact names; sources and rules in `research/tenders-sources.md`; mr.gov.il candidates via `scripts/tenders_mrgov.py` (polite, ≤40 requests).
- Rates survey: `/survey` (landing), `/survey/start` (questionnaire), `/survey/results`. Questions, bands and close date in `lib/survey/config.js` (the companies app gets the date at build time). Answers in Supabase `survey_responses`: written only through `/api/survey` (service role), owner can read their own. Results come from a daily snapshot (`survey_snapshots`, at most once per 24h and only after ≥5 new answers); groups under 5 are left out, exact numbers count only from 10, shares rounded to 5%, group sizes shown as buckets, free text never shown. Checks: `node scripts/test-survey.mjs`. Never ask for client or company names.
- Stage 1 (now): an information channel + newsletter. Nobody builds a profile: `/onboard` redirects to `/digest`, `/p/*` is 404, `/me` is only the account (digest settings, survey, delete), and there is no "זה אני" on listed people (removal stays). It's one flag, `PROFILES` in `lib/chrome.mjs` (`NEXT_PUBLIC_PROFILES=on` brings profiles back; the code stays). Header call to action is the weekly digest.
- Theme: light by default on both apps, whatever the device. The header toggle (`THEME_BUTTON`, `THEME_SCRIPT` in `lib/chrome.mjs`) cycles בהירה → כהה → לפי המכשיר and stores it in localStorage (`landscape-theme`); CSS reads `html[data-theme]` (`dark`, or `system` + prefers-color-scheme). Inside the Artifact host the companies app still follows the device.
